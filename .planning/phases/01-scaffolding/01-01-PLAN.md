  <name>Task 1: Install dependencies and configure tooling</name>
  <files>package.json, biome.json, eslint.config.mjs, .husky/pre-commit</files>
  <action>
    1. Install all production dependencies:
       pnpm add @supabase/supabase-js @supabase/ssr zod @t3-oss/env-nextjs @sentry/nextjs @sentry/core @phosphor-icons/react
    2. Install all dev dependencies (note: better-sqlite3 is dev-only — only used when SENTRY_LOCAL=true):
       pnpm add -D vitest @vitejs/plugin-react @playwright/test @biomejs/biome husky lint-staged better-sqlite3 @types/better-sqlite3 jiti @testing-library/react @testing-library/jest-dom jsdom
    3. Create biome.json with:
       - formatter: space indent (2), 100 line width, LF line endings
       - linter: recommended rules + noUnusedVariables + noUnusedImports as errors
       - CSS linting enabled
       - VCS: git, useIgnoreFile true, defaultBranch main
       - files.ignore: node_modules, .next, out, build
    4. Slim eslint.config.mjs to ONLY eslint-config-next/core-web-vitals and typescript rules.
       Remove ALL formatting rules — Biome handles formatting exclusively.
       This prevents Biome/ESLint conflicts in lint-staged.
    5. Run: pnpm exec husky init
    6. Set .husky/pre-commit content to: pnpm exec lint-staged
    7. Run: chmod +x .husky/pre-commit (ensure executable in Conductor worktrees)
    8. Add lint-staged config to package.json:
       "lint-staged": {
         "*.{js,jsx,ts,tsx}": ["biome check --write", "eslint --fix"],
         "*.{json,css,md}": ["biome check --write"]
       }
       IMPORTANT: Biome runs FIRST, then ESLint. Biome handles formatting, ESLint handles Next.js rules only.
    9. Update package.json scripts:
       "check": "biome check .",
       "format": "biome check --write .",
       "lint": "eslint .",
       "typecheck": "tsc --noEmit",
       "test": "vitest run",
       "test:watch": "vitest",
       "test:e2e": "playwright test",
       "prepare": "husky"
  </action>
  <verify>
    - pnpm check runs without errors
    - pnpm typecheck passes
    - pnpm lint runs without errors
    - .husky/pre-commit exists and is executable (ls -la .husky/pre-commit)
    - Verify no rule conflicts: run both biome check and eslint on the same file, confirm no contradictory fixes
  </verify>
  <done>Biome, ESLint, Husky, and lint-staged are configured. All check/lint/typecheck scripts pass. Biome and ESLint do not conflict.</done>

<task type="auto">
  <name>Task 2: Shadcn/ui init, t3-env, error boundaries, and base layout</name>
  <files>components.json, src/lib/env.ts, next.config.ts, src/app/globals.css, src/app/layout.tsx, src/app/page.tsx, src/app/error.tsx, src/app/global-error.tsx, src/components/error-boundary.tsx, .env.example</files>
  <action>
    1. Run: pnpm dlx shadcn@latest init --preset b3XobJslQO --defaults
       This creates components.json and updates globals.css with Lyra theme CSS variables.
    2. Create src/lib/env.ts with createEnv from @t3-oss/env-nextjs:
       - server: SENTRY_DSN (z.string().optional()), SENTRY_LOCAL (z.string().optional()),
         SUPABASE_URL (z.string().url().optional()), SUPABASE_SERVICE_ROLE_KEY (z.string().optional())
       - client: NEXT_PUBLIC_SENTRY_DSN (z.string().optional()), NEXT_PUBLIC_SENTRY_LOCAL (z.string().optional()),
         NEXT_PUBLIC_SUPABASE_URL (z.string().url().optional()), NEXT_PUBLIC_SUPABASE_ANON_KEY (z.string().optional())
       - experimental__runtimeEnv for all client vars
       - NOTE: Supabase vars are optional in Phase 1. Phase 2 will make them required.
    3. Update next.config.ts to import env.ts via jiti for build-time validation.
       CRITICAL: Use relative path "./src/lib/env" in the jiti call, NOT the @/ alias.
       The @/ alias is not resolved at config-load time before TypeScript compilation.
    4. Create src/components/error-boundary.tsx:
       - MUST have 'use client' directive (componentDidCatch only works in client components)
       - Class component with componentDidCatch logging to console.error
       - Fallback UI with "Something went wrong" message and "Try again" button (calls reset)
       - Accepts children and optional fallback prop
    5. Create src/app/error.tsx:
       - 'use client' directive (required by Next.js convention)
       - Receives { error, reset } props
       - Renders error message with reset button
       - Calls console.error(error) in useEffect
       - This catches route-level rendering errors automatically
    6. Create src/app/global-error.tsx:
       - 'use client' directive
       - Receives { error, reset } props
       - Renders full HTML shell (html + body tags) since root layout may have errored
       - This catches errors in the root layout itself
    7. Update src/app/layout.tsx:
       - Wrap children with ErrorBoundary (for client-side subtree errors)
       - Update metadata title to project name, description to template description
       - Keep Geist fonts
    8. Replace src/app/page.tsx with a clean home page:
       - App name heading with a Phosphor icon (e.g., RocketLaunch from @phosphor-icons/react)
       - Brief description: "Production-ready Next.js starter template"
       - Simple card layout showing the tech stack (demonstrates Shadcn + Phosphor working)
       - Use Shadcn Button component (add via: pnpm dlx shadcn@latest add button)
    9. Create .env.example with all env vars documented (placeholder values only, never real secrets):
       SENTRY_LOCAL=true
       SENTRY_DSN=
       NEXT_PUBLIC_SENTRY_LOCAL=true
       NEXT_PUBLIC_SENTRY_DSN=
       SUPABASE_URL=
       SUPABASE_SERVICE_ROLE_KEY=
       NEXT_PUBLIC_SUPABASE_URL=
       NEXT_PUBLIC_SUPABASE_ANON_KEY=
  </action>

    - error.tsx renders when a route component throws (test manually or check file exists)
    - global-error.tsx exists with full HTML shell
    - ErrorBoundary has 'use client' directive
  </verify>
