  <action>
    1. Create `src/app/(auth)/login/actions.ts` — server actions for `login` and `signup` using ActionState type. Each action: create server client, call `supabase.auth.signInWithPassword` or `supabase.auth.signUp`, return ActionState with errors or success, call `revalidatePath('/', 'layout')` and `redirect('/')` on success. If Supabase client is null, return error "Supabase is not configured".

    2. Create `src/app/(auth)/login/page.tsx` — client component with shadcn Input, Button, and the project's SubmitButton. Two tabs or sections: email/password form (using `useActionState` with the login/signup actions) and OAuth buttons (Google, GitHub) using `supabase.auth.signInWithOAuth`. Use sonner toast for error feedback. Include `aria-label` and `data-testid` on key elements for future E2E tests.

    3. Create `src/app/auth/callback/route.ts` — GET handler that exchanges PKCE code via `exchangeCodeForSession`. Include open-redirect prevention (`next` param must start with `/`). Handle x-forwarded-host for production deployments.

    4. Create `src/app/(protected)/layout.tsx` — server component that checks `getUser()`. If Supabase is not configured (client is null), render children without auth gate. If configured but no user, `redirect('/login')`.

    5. Create `src/app/(protected)/dashboard/page.tsx` — simple server component showing user email and a sign-out button. This proves the protected route pattern works.

    Read research for exact patterns. Use shadcn components from the project (Button, Input are already installed). Import SubmitButton from `@/components/submit-button`. Import ActionState from `@/lib/actions/types`.
  </action>
